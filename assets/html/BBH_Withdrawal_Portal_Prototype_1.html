What's happening
The home screen of the BBH customer app. Initial state: customer has no linked TIB account and no wallet balance. The app prompts them to link a TIB account so they can fund the wallet — choosing "Link account" begins API 7.1 flow.

About This Prototype

This is an interactive demonstration of the BBH withdrawal flow — customer takes money out of their BBH wallet, back to their already-linked Al-Taif Islamic Bank account.

Pre-linked state

The customer's TIB account is already linked when the prototype opens. Linking happens once, earlier in the customer lifecycle (typically during onboarding or before the first deposit). The account_ref_token from that linking step persists — it's reused for every subsequent deposit and withdrawal. No relinking is required for withdrawal. See the deposit prototype for the linking flow itself.

The withdraw flow (API 4.3 + 3.1/3.2)

Customer moves money from their BBH wallet back to their linked TIB account, confirmed via TIB-issued OTP. Same POST /transfers/instant endpoint as deposit, with source: BBH_SEGREGATED_CLIENT and destination_account_ref_token reversed. OTP-gated for per-transaction explicit consent.

How to use

  • Click buttons inside the phone to advance the flow.
  • Watch the API Activity panel on the right — every step that involves a TIB API call is logged.
  • The annotation bar at the bottom explains what's happening at each screen in plain language.
  • Use Reset to return to the withdraw home screen (the linked-account state is preserved).

Status

Prototype only — no real money moves, no real TIB endpoint is called. All amounts, account numbers, customer IDs, and OTP codes are fixed demo values.

The deposit flow lives in a separate prototype file (BBH_Funding_Portal_Prototype.html), which also includes the one-time linking step.
